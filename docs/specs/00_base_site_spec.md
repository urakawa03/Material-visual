# 母体サイト仕様書 — インタラクティブ材料科学教材(v1.0)

**この文書の役割**: 本書は Claude Code に渡し、教材サイトの「母体」= 全記事が共通して乗る基盤(デザインシステム・コアライブラリ・ページ雛形)を実装させるための仕様書である。各テーマ(コットレル雰囲気ほか全7本)の記事内容は、本書の規約に従う個別仕様書として別途作成し、`docs/specs/` に追加していく。本書と個別仕様書が矛盾した場合、基盤に関する事項は本書を優先する。

## 1. プロジェクト概要

- **目的**: 材料科学の代表的な現象・概念を、Bartosz Ciechanowski のサイトに代表される「長文記事 + 本文に埋め込まれた操作可能な図版」のスタイルで、基礎から体感的に学べる教材サイトを作る。
- **想定読者**: 材料系の学部生・高専生・大学院初年度、および社会人の独学者。高校物理と初歩の結晶学の知識を仮定し、不足分は記事内で補う。
- **形態**: 完全な静的サイト。サーバ・DB・ログイン・アナリティクスは持たない。
- **言語**: 日本語のみ(`lang="ja"`)。コードの識別子は英語、コメントは日本語可。
- **サイト名**: 仮称「**うごく材料科学**」(英題仮: _Materials in Motion_)。プレースホルダとして実装し、後から一箇所の定数で差し替えられるようにする。

## 2. デザイン原則(最重要・全実装の判断基準)

実装で迷ったら常にこの節に立ち返ること。以下に反する実装は差し戻し対象とする。

1. **文章と図版の一体化** — 図版は挿絵ではなく本文の一部。本文が「上のスライダーを右へ動かすと…」のように操作を促し、図版がそれに応える。図版だけ見ても、本文だけ読んでも成立しないように書く。
2. **段階的構築** — 各記事は最小の系(原子1個、転位1本、格子点1個)から始め、1節ごとに要素を1つだけ追加する。一度導入したビジュアル言語(色・形・記号)は記事の最後まで変えずに使い回す。
3. **すべての図は触れる** — 眺めるだけの動画・GIFは置かない。どの図版も最低1つのパラメータを操作できる。自動再生ループ + いつでも介入可能、が基本形。
4. **直感が先、数式は後** — まず操作で現象を体感させ、その後に定式化する。数式中の変数は、図中の対応する要素と同じ色で示す。
5. **誠実な簡略化** — 教育目的の簡略化(2D化、スケールの誇張、線形化、粒子数の削減)は必ず図注で明示する。
6. **遊べる余白** — パラメータ範囲は「現実的な値」の少し外側まで開放し、極端な条件で何が起きるかを読者が試せるようにする。
7. **静かな美学** — 白背景・限定パレット・装飾なし。影・グラデーション・演出目的のアニメーションは使わない。**画面上で動くのは物理だけ**。
8. **常に速い** — 図版がいくつあってもスクロールは滑らか。画面外の図版は完全停止し、CPU/GPUを消費しない。

このサイトの「シグネチャ」は、全記事で統一された**意味カラーパレット**(§6.2)と、標準化されたインタラクティブ図版そのものである。それ以外の装飾で個性を出そうとしないこと。

## 7. コアライブラリ(`src/core`)

### 7.1 `engine.ts` — 図版実行環境

責務:

- ページ内全ウィジェット共通の**単一** `requestAnimationFrame` ループ。`dt` は 50ms でクランプして渡す。
- **IntersectionObserver**: `rootMargin: 600px` 圏内に入ったらウィジェットモジュールを動的 import して初期化。可視になったら再生、画面外・タブ非表示(`visibilitychange`)で停止。ユーザーが手動で一時停止した図版は可視に戻っても再生しない。
- **ResizeObserver** + devicePixelRatio(上限 2)でキャンバスのバッキングストア寸法を管理し、変化時に `resize` を通知。
- `prefers-reduced-motion: reduce` の場合: 自動再生せず、意味のある静止フレーム + 目立つ再生ボタンで開始。スライダー操作は 1 フレーム描画で即時反映。
- 物理シミュレーション向けに固定タイムステップ補助 `fixedStep(stepMs)`(アキュムレータ方式)を提供。

### 7.2 `controls.ts` — 操作部品

提供する部品: `slider`(線形/対数、単位、値フォーマッタ)、`toggle`、`segmented`(排他選択)、`button`、`playPause` + `reset`。

規約:

- 実体はネイティブ要素(`<input type="range">` 等)をスタイルしたもの。**キーボードだけで全操作可能**であること。
- レイアウト: ラベル左・現在値右(tabular-nums)・単位付き。行間 12px で縦積み。
- タッチターゲットは 44px 以上(見た目のつまみは 20px 円でよい)。
- 値変更は即時反映(Apply ボタン方式は禁止)。

参考シグネチャ(細部は実装で調整可):

```ts
const T = host.controls.slider({
  id: "T", label: "温度", min: 300, max: 900, step: 5, value: 600, unit: "K",
});
T.onChange((v) => { /* 即時反映 */ });
host.controls.playPause();          // engine と連動
host.controls.reset(() => { ... }); // 初期状態へ(乱数はシード固定で再現)
```

### 7.3 `mathx.ts`

`Vec2` / `Vec3`、`clamp` / `lerp` / `smoothstep` / `remap`、シード付き乱数(mulberry32)、イージング数種。毎フレームのオブジェクト割当てを避けられる API 設計(結果書き込み先を渡せる形)とする。

### 7.4 `three-helpers.ts`(3D ページのみ)

- 白背景・ライト・DPR 設定済みのシーン雛形。
- 簡易オービット操作: 慣性つきドラッグ回転 + ピンチ/ホイールズーム、上下角に制限。タッチ・マウス両対応。
- `InstancedMesh` で原子群(数千個)を描くヘルパ。
- three 本体ごと動的 import され、2D のみのページのバンドルには一切含まれない。

### 7.5 数式(`M.astro`)

- KaTeX をビルド時に `renderToString` し、クライアントには HTML + KaTeX CSS のみ配信。
- インライン `<M tex="…" />`、別行 `<M block tex="…" />`。
- 数式中の変数を意味パレット(§6.2)の色で塗るためのマクロ(class ベースで可)を用意する(デザイン原則 4)。

## 8. インタラクティブ図版の規約

### 8.1 DOM 構造(`Figure.astro` が出力)

```html
<figure
  class="ix"
  id="fig-frank-read-loop"
  data-widget="frank-read/loop"
  data-aspect="16/10"
>
  <div class="ix-stage"><canvas aria-hidden="true"></canvas></div>
  <div class="ix-controls"><!-- controls.ts が生成 --></div>
  <figcaption>
    図3. 両端を固定された転位が張り出し、ループを放出するまで。
  </figcaption>
  <p class="sr-only"><!-- alt: スクリーンリーダー向けの内容説明 --></p>
</figure>
```

`Figure.astro` の props: `widget`(必須, `"<slug>/<name>"` 形式)、`aspect`(既定 `16/10`)、`caption`、`alt`(必須)、`maxWidth`(任意)。図番号は記事内の通し番号を手書きする(自動採番はしない)。

### 8.2 ウィジェット契約(`src/widgets/types.ts`)

```ts
export interface FigureHost {
  stage: HTMLElement;
  canvas: HTMLCanvasElement;
  controls: Controls; // §7.2
  size: { w: number; h: number; dpr: number };
  onFrame(cb: (dt: number, t: number) => void): void; // 連続アニメ用
  requestRender(): void; // 操作時のみ再描画する図版用
}

export interface WidgetHandle {
  resize?(): void;
  setPlaying?(playing: boolean): void;
  destroy(): void;
}

export type WidgetFactory = (
  host: FigureHost,
) => WidgetHandle | Promise<WidgetHandle>;
```

- **1 図版 = 1 モジュール**。`src/widgets/<slug>/<name>.ts` が `WidgetFactory` を default export する。
- `registry.ts` に `"frank-read/loop": () => import("./frank-read/loop")` の形で登録。
- 連続アニメが不要な図(操作時のみ変化)は `onFrame` を使わず `requestRender` 方式にし、アイドル時の消費をゼロにする。
- 乱数はシード固定。`reset` で完全に同じ初期状態に戻る。

### 8.3 パフォーマンス規約

- 1 フレーム中の新規割当てを避け、TypedArray / 配列を再利用する。
- 2D で原子 500 個超は 1 パスでまとめ描き。3D は `InstancedMesh`。
- 各図版は中位スマートフォンで 60fps(最低 30fps)を守る設計。重い場合は粒子数・解像度を画面幅で自動スケール。
- ページ全体で同時に動く図版は事実上ビューポート内の 1〜2 個(engine が保証)。

## 9. ページ仕様

### 9.1 トップページ `/`

- ヒーロー: サイト名 + 副題 2 文程度(「材料の中で起きていることを、触りながら理解する」の趣旨。文言は実装時に提案してよい)。派手な演出は不要。
- §1 の 3 カテゴリごとに `TopicCard` を並べる。カード = 静的 SVG サムネイル(意味パレットで描いた簡単な模式図。将来のアニメ化は任意)+ タイトル + 一行説明 + 前提バッジ + 公開状態(公開 / 準備中)。
- 準備中の記事はリンク無効のカードとして最初から 7 枚全て表示する。
- フッター: About へのリンク、ライセンス表記(プレースホルダ)。

### 9.2 記事レイアウト(`layouts/Article.astro`)

上から順に:

1. カテゴリラベル(小さく)
2. h1 タイトル
3. リード文(2〜3 文)
4. 前提バッジ(あれば)
5. 本文: h2 節 × 5〜8、各節に図版 0〜2
6. 「まとめ」節
7. 「もっと知るには」節(参考文献・教科書)
8. 前後の記事ナビ
9. フッター

**文章スタイル規約**(全記事共通): です・ます調 / 一文は短く / 専門用語は初出で英語併記(例: 逆格子(reciprocal lattice))/ 図版の直前か直後に操作を促す一文を必ず置く / 簡略化は図注で明示(§2-5)。

### 9.3 `style-guide` ページと参照ウィジェット

掲載内容: デザイントークン一覧(色見本・意味パレット)、タイポグラフィ見本、全コントロール部品、数式サンプル(色付き変数を含む)、そして参照ウィジェット。

**参照ウィジェット `_sample/brownian`(ブラウン運動デモ)の仕様**:

- 白い箱の中を `--mat-matrix` 色の原子 60 個が熱運動する 2D デモ。
- スライダー「温度」(100〜1200 K)で運動の激しさが変わる。
- 1 個だけ `--mat-solute` 色の原子があり、ドラッグで掴んで放せる(タッチ確認用)。
- `playPause` / `reset` 付き。シード固定。
- 目的は物理の正確さではなく、engine / controls / DPR / タッチ / 省モーション / 画面外停止の**全機構の動作確認**。

### 9.4 About `/about/`

サイトの狙い・想定読者・「誠実な簡略化」ポリシー・連絡先プレースホルダ。1 画面程度。

## 10. 品質要件

### 10.1 パフォーマンス

- 記事ページ(2D のみ)の初期 JS 合計 **120KB gzip 以下**。three.js は該当ページのみ・最初の 3D 図版への接近時に遅延読み込み。
- Lighthouse(モバイル)Performance / Accessibility とも **90 以上**(style-guide を除く)。
- スクロール中に 50ms を超える長タスクを発生させない。

### 10.2 アクセシビリティ

- 全図版の全操作がキーボードのみで実行可能。フォーカスリング可視(`--color-accent` 2px)。
- 各図版に日本語の `sr-only` 説明(`alt` prop 必須)。
- テキストコントラストは AA を満たす(図中ラベルは `--color-text-2` 以上の濃さ)。
- `prefers-reduced-motion` 準拠(§7.1)。

### 10.3 対応環境

- Chrome / Edge / Firefox / Safari の最新 2 バージョン、iOS Safari 16+、Android Chrome。
- タッチとマウスの両対応。ホバーにしかない操作を作らない。
