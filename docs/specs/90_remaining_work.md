## 3. P0 — 共通基盤の整備(記事の実装より先に、単独で行う)

**目的は 2 つ**: (1) コピーされた補助関数を 1 箇所にまとめ、新しい 6 記事がさらにコピーを増やさないようにする(D-1)。(2) 記事どうしが同じ共有ファイルを書き換えないで済むように、共有ファイルへの追記を先に済ませておく(前回の 4 本の並行実装でコンフリクトした `registry.ts`・CSS・`_shared` の型が対象)。

**P0 は 1 本のブランチで行い、記事のどれかに着手する前に `main` にマージする**。所要は小さい(新規ファイル 3 つ + 共有ファイルへの数行の追記)。既存の記事の見た目は変えない(新しい「準備中」カードが 3 枚増えるのを除く)。

### 3.1 `src/core/units.ts` — 物理定数と単位の書式

現状、`KB_EV` が 5 箇所(`cottrell-atmosphere`・`kirkendall-effect`・`gp-zones`・`ostwald-ripening` は 8.617e-5、`band-theory` は 8.617333e-5)、`formatDuration` が 4 箇所(実装は 3 通り)にある。

| 名前                | 値 / 役割                                                                                                                         |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `KB_EV`             | 8.617333262 × 10⁻⁵ eV/K(CODATA 2018)                                                                                              |
| `KELVIN_OFFSET`     | 273.15                                                                                                                            |
| `R_GAS`             | 8.314462618 J/(mol·K)                                                                                                             |
| `EV_TO_KJ_PER_MOL`  | 96.485                                                                                                                            |
| `Q_E`               | 1.602176634 × 10⁻¹⁹ C                                                                                                             |
| `EPS0_F_PER_CM`     | 8.8541878128 × 10⁻¹⁴ F/cm                                                                                                         |
| `HBAR2_OVER_2ME`    | 0.0380998 eV·nm²(バンド理論の `HBAR2_OVER_2M` と同値)                                                                             |
| `HBAR_EV_FS`        | 0.6582119569 eV·fs                                                                                                                |
| `formatDuration(s)` | 秒 → 「0.3 秒」「12 分」「3.5 時間」「4.2 日」「7600 年」「宇宙の年齢の 10⁹ 倍」(既存 3 通りの上位互換。年の上は宇宙の年齢との比) |

**既存記事の移行は任意**とする。`8.617e-5` → `8.617333e-5` は相対 4 × 10⁻⁵ の変更で、指数の中に入ると図の数値が表示桁で動く可能性がある。移行するなら記事ごとに別コミットにし、既存のテストがすべて通り、読み取りの表示値が変わらないことを確認する。**新しい 6 記事は必ずこちらを使う**(各仕様書に記載済み)。

### 3.2 `src/core/plot.ts` — グラフの目盛りと数値の書式

`linTicks`・`logTicks`・`fmtPow10`・`font`(フォントの指定)は `kirkendall-effect`・`gp-zones`・`ostwald-ripening` の `lib/draw.ts` に**一字一句同じ内容**でコピーされている(空白を正規化して比較済み)。`fmtSig` と `arrow` は 2 通りある。

| 名前                              | 役割                                                              |
| --------------------------------- | ----------------------------------------------------------------- |
| `FONT_STACK` / `font(px, weight)` | 図中の文字のフォント(母体 §6.3 のスタック)                        |
| `linTicks(min, max, target)`      | 線形軸のきりのよい目盛り                                          |
| `logTicks(min, max)`              | 対数軸の 10 のべき乗の目盛り                                      |
| `fmtPow10(v)`                     | `1.2 × 10⁴` 形式(上付き数字)                                      |
| `fmtSig(v, digits)`               | 有効数字の表示(2 通りの実装のうち、`digits` を引数にとる方に統一) |

`arrow`(矢印の描画)は記事ごとに見た目の細部が違うので、P0 では統合しない(新しい記事は `reciprocal-lattice/_shared2d.ts` の `drawArrow` を使う)。既存記事の移行は 3.1 と同じく任意。

### 3.3 `src/core/anim.ts` — 操作直後の短い遷移

`tween` は記事に依存しない汎用部品だが `frank-read-source/lib/anim.ts` にある。中身をそのまま `src/core/anim.ts` へ移し、`frank-read-source/lib/anim.ts` は `export { tween, type Tween } from "../../../core/anim";` の 1 行にする(フランク・リード源の挙動は変わらない)。新しい記事(フェルミ準位 図7・pn 接合・マルテンサイト 図1/図5)はこれを使う。

### 4.2 pn 接合のサムネイル(C-2)

`topicThumbs.ts` の `pnJunction()` は、バンドが 1 本で両端が同じ高さ・中央がへこんだ V 字になっており、電子(`--mat-electron`)が左下、正孔(`--mat-hole`)が右上に置かれている。物理的に、電子は n 側の伝導帯の上、正孔は p 側の価電子帯の下にいる。仕様書 13 §6.1 S-1 のとおり、**$E_c$ と $E_v$ の 2 本が左(p)で高く右(n)で低い段差になり、接合面で滑らかに曲がる**形に描き直し、電子は右の $E_c$ のすぐ上、正孔は左の $E_v$ のすぐ下に置く。P0 の 3.4-2 で行う。

## 6. 実装順と、並行実装の規則

```
P0(共通基盤 + 下準備 + C-1・C-2 の修正)── 単独でマージ
   │
   ├── 第 1 波(並行してよい): #12 フェルミ準位 / #3 構造因子 / #9 スピノーダル / #10 マルテンサイト / #14 トンネル効果と STM
   │
   └── 第 2 波: #13 pn 接合(#12 のマージ後 — #12 が作る共有モジュールを使う)

仕上げ(いつでも): P-1(発注者判断)・P-2 OGP・P-3 ダミー記事の削除・P-5 計測
```

**第 1 波を並行してよい理由**: P0 の下準備(§3.4)のあと、各記事のブランチが触る共有ファイルは次だけになる。

| 共有ファイル               | 各記事の変更                            | 衝突                                   |
| -------------------------- | --------------------------------------- | -------------------------------------- |
| `topics.ts`                | 自分の 1 行を `published: true` に      | 行が離れているので衝突しない           |
| `registry.ts`              | 自分のアンカーの直下に登録行を追加      | アンカーの間に空行があるので衝突しない |
| 他記事のページ(相互リンク) | §4.1 の「相手の公開時に直す」表のとおり | 直す行が記事ごとに違うので衝突しない   |
| `_shared/banddiagram.ts`   | **#12 だけ**が拡張する                  | 第 1 波で触るのは #12 だけ             |
| `src/core/fft.ts`          | **#9 だけ**が新設する                   | 新規ファイルなので衝突しない           |

それでも**マージは 1 本ずつ**行い、マージのたびに `main` を取り込んでから次をマージする(前回の経験から)。第 1 波の 5 本はどの順でマージしてもよい。

**各記事のセッションへの依頼**: `docs/prompts/<番号>_<slug>_prompt.md` を読ませる(プロンプトの冒頭に「仕様書は作成済み — フェーズ 2 から」と追記してある)。**仕様書とプロンプトが食い違う場合は仕様書を優先**する(仕様書のほうが、実装済みの共有モジュールの実際の API と、本書の作成時に行った数値検証を反映している)。
